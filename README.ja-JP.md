# 長夜幻境（EvernightRealm）

> あなた自身のマシンで、仲間のためのプライベートな仮想世界を — アクティビティ管理、キャラクター、仮想アセット。

[English](./README.md) · [简体中文](./README.zh-CN.md) · [繁體中文（台灣）](./README.zh-TW.md) · [日本語](./README.ja-JP.md)

## これは何？

長夜幻境（ちょうやげんきょう／EvernightRealm）は、自己ホスト型・オフライン優先のプラットフォームです。小規模なプレイヤーグループが没入型アクティビティを一緒に進め、キャラクターを演じ、仮想アセットを取引できます — すべてローカルネットワーク内で完結し、インターネットもクラウドアカウントもテレメトリも不要です。

## 機能（開発中）

- **没入型アクティビティ** — グループ向けにシーン、フェーズ、イベントを編成
- **キャラクターとアイデンティティ** — プレイヤー・NPC・管理者の役割が共存するプライベートな世界
- **仮想アセット** — 真正な所有権と監査可能な取引
- **プライベートチャット** — メッセージは自分のサーバーだけに保存
- **オフラインファースト** — すべて自分のマシンで動作し、クラウドに依存しない

## 現在の状況

サーバーにはさらに、**整合性のあるバックアップパッケージ**を作る運用コマンドがあります。単一ファイルのデータベーススナップショット（サーバー稼働中でも取得でき、稼働中の WAL 主ファイルをコピーするのではありません）に設定ファイルとメディア／文書／アップロードディレクトリを添え、各ファイルのサイズと SHA-256 をリストに記録します。対応する `restore` コマンドで、このパッケージを**新しい空のデータディレクトリ**へ復元できます。マニストに従い全ファイルのチェックサムを再計算し、スナップショットのデータベース実体を着地前後で二回読み取って照合します。既存ディレクトリは上書きしません（上書きしたい場合は当該ディレクトリを先に自分でバックアップしてください）、実行ファイルより新しいスキーマ版の復元は拒否し、復元操作自体をサーバー側監査記録として書き込みます。バックアップの暗号化と旧パッケージの自動削除はまだ未実装です。

一度限りの Root 初期化は**ローカルコマンドだけが入口です**：

    evernight-server init-root --password-stdin --data-dir <データディレクトリ>

標準入力からパスワードを読み取り（先頭の 2 行は本体と確認）、そのデータディレクトリの `config.yaml` に Argon2id のハッシュとして保存します。平文は書かず、初期パスワードを自動生成して表示することもありません。サーバーの最高権限を渡す認証は「サーバーのホストでコマンドを実行できること」なので、この手順は HTTP エンドポイントも待ち受けポートも一切開きません。CORS、クライアントが自己申告したアドレス、画面からボタンを隠す、どれも認証にはなりません。サービスが単一書き込みインスタンスロックを保持している間、`ER_SECURITY_ROOT_PASSWORD_HASH` が設定されている間、監査テーブルがまだ存在しない間はすべて拒否し、書き込み成功後は二度と開放されません（パスワードの交代は認証済みのサービス内フローで行い、Root でサインイン後に `POST /auth/password/change` を使います。次の段落のローカル復旧が該当するのは、本当にパスワードを失念した場合だけです）。読み取り専用の `evernight-server root-status` は「いま Root があるか」だけを答え、ファイルを作成も変更もせず、設定パス・ハッシュ・導入手順上の秘密は一切返しません。成功も拒否も Root 監査テーブルに記録され、パスワードは残りません。

失念した Root パスワードの復旧も、ローカルコマンドだけが入口です：

    evernight-server recover-root --password-stdin --confirm --data-dir <データディレクトリ>

このコマンドも標準入力から新しいパスワードを読み取り（先頭の 2 行は本体と確認）、コマンドライン上のパスワード値は一切受け取りません。また、サービスの停止を要求します：稼働中のサービスは認証情報をメモリに読み込んでおり、設定ファイルを書き換えてもそれを再読み込みしないためです。そうなると「端末は成功だと言ったのに、旧パスワードはまだ通る」という、拒否よりも調査の難しい状態が生まれます。復旧は旧パスワードを尋ねず、検証もしません——このホストでコマンドを実行でき、この設定ファイルを読み書きできること自体が、この操作の認証のすべてです。ゆえにバックドア用パスワード、ダウンロード可能な復旧ファイル、HTTP エンドポイントも一切ありません。成功時は設定ファイル内の認証情報が新しいパスワードの Argon2id エンコードに置き換わり、Root 配下の全セッションが同一のデータベーストランザクション内で取り消され（次のリクエストから拒否されます）、`server.root_recover` の監査記録が 1 件残ります。通常アカウントのセッションは 1 つも動きません。取り消しと監査が書き込めない場合は、設定ファイルを書き換える前の認証情報に戻して失敗を返し、利用可能な状態は着手前と一致します（ロールバックさえ失敗する二重障害は、実行ログのファイルに Error として残り、手動での追記を明示的に要求します）。`--confirm` は明示的に必要なフラグです。上書きの代償は、旧パスワードの恒久的な失効と Root の全端末のサインアウトだからです。設定ファイルにまだ認証情報が無い場合は拒否して `init-root` を案内し、逆に、既存の値が壊れて復号不能（誰もサインインできない状態）でも復旧はできます——これはまさに `init-root` が拒否する形であり、二つの書き込み経路はそれぞれ成功形態を一つだけ持ちます。

初めての起動画面は「未初期化」を正直に示す必要があるため、サーバー側は読み取り専用の `GET /root/init-status` にも答えます。返すのは 3 つの真偽値だけです（設定ファイルの有無、Root 認証情報の有無、環境変数による上書きが設定されているか）。パス・長さ・認証情報の断片は返さず、データベースにも監査にも書き込みません。これは「有るか無いか」を言うのであって「どう変えるか」ではありません。Root の初期化は引き続き、サーバー本体で実行する `init-root` だけが経路です（失念したパスワードの書き換えは上の `recover-root` が担い、どちらもネットワーク越しには到達できません）。

長夜幻境は活発に開発中で、安定版は未リリースです。サーバーはすでに**単一の実行ファイル**としてビルドできます：同じポートがウェブ画面（現在はアプリのシェル部分で、表示言語の切替とサーバー接続の試行が可能。業務機能は開発中）と API エンドポイントの両方を提供する為、ブラウザでそのアドレスを開くだけで利用でき、静的ホスティングを別途用意する必要はありません。

## リリース後の利用方法（予定）

- 誰か一人が自分のマシン（Windows または Linux）でサーバーをホスト
- 他の参加者は同じローカルネットワーク内のブラウザから接続
- 第三者登録は不要。データはホスト機だけに保存

## 対応言語

簡体中文、繁体中文（台湾）、English、日本語。

## ソースからのビルド

Windows 実行ファイルのアイコンは生成されるもので、バージョン管理には含まれません。`cmd/evernight-server/resource_windows_*.syso` は `assets/icons/EvernightRealmBackendRounded.ico` から生成されます。クローン直後はビルドの前に

    python tools/icons/generate_icons.py

を実行してください。実行しないとアイコン無しの実行ファイルができあがりますが、`go build` は何も報告しません。`python tools/icons/generate_icons.py --check` は現状を照合するだけで、何も書き込みません。詳細は `tools/icons/README.md`。
